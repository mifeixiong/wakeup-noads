# wakeup-noads

WakeUp 课程表的非官方精简版本，聚焦高校教务系统课表导入与本地课表管理。

> [!IMPORTANT]
> 本项目由社区独立维护，与原应用开发者、运营方、广告平台及各高校教务系统不存在隶属、合作或背书关系。

> [!NOTE]
> 本文只记录跨版本稳定的使用边界和维护规则，不绑定某一个上游版本。每个构建的上游版本、功能变更、哈希和验证状态见 [版本记录](./RELEASE_RECORDS.md) 与对应 Release。

## 项目定位

本项目面向仅需要课表核心功能的用户，通过精简与课表无关的业务入口，降低广告、账户体系和云服务对使用体验的影响，同时尽量保持本地课表及高校教务系统导入流程不变。

README 记录跨版本稳定的使用边界和维护规则。每个构建所基于的上游版本、兼容范围、文件摘要和验证结果以对应的 [Release](../../releases) 说明及 [版本记录](./RELEASE_RECORDS.md) 为准。

## 功能范围

### 保留

- 本地课表查看、编辑与管理。
- 高校列表及高校教务系统 Web 登录。
- 高校课表页面解析与导入。
- 本地课表文件导入、日历文件（ICS）导出和课表样式设置。
- 高校教务系统访问所需的网络能力。

### 默认精简范围

- 开屏、插屏、信息流等广告入口。
- 学习、搜题及关联助手页面。
- 应用账户、用户资料和会员相关入口。
- 收藏、已购课程及网络推广内容。
- 课表、日历和样式的云同步入口。
- “我的”页电脑端扫码及 PC 插件登录入口。
- 普通软件更新提醒、自动更新检查和服务端强制更新弹窗。
- 与广告标识、设备标识和广告定位相关的非必要声明。

导入/导出中的“分享口令导入”“在线分享课表”“分享 App”，以及“我的 - 更多 - 个人信息导出”均不属于精简版范围，已从运行入口中移除；本地文件导入和 ICS 导出仍保留。

> [!NOTE]
> 以上是项目的默认精简目标，具体构建可能因上游实现和验证结果调整。以对应 Release 与版本记录为准。为维持原应用混淆代码的类链接关系，构建中可能保留部分第三方 SDK 二进制类；保留类文件不代表对应业务入口仍处于启用状态。

## 下载与安装

1. 前往 [Releases](../../releases) 下载所需版本的 APK。
2. 阅读该版本的兼容性、变更内容、已知问题和签名说明。
3. 按 Release 提供的 SHA-256 摘要校验文件完整性。
4. 备份现有课表及其他重要数据后再执行安装。
5. 查看该 Release 是否关闭应用内更新检查；若已关闭，后续版本需要手动关注 Releases。

项目保留原应用包名：

```text
com.suda.yzune.wakeupschedule
```

发布包使用项目证书签名，与原应用开发者证书不同。因此，从官方版本迁移时，Android 通常会因签名不一致而拒绝直接覆盖安装；卸载原应用可能同时清除其应用数据。使用同一项目证书签名的精简版本之间通常支持覆盖升级，具体以对应 Release 说明为准。

## 完整性校验

每个 Release 应至少提供以下信息：

- 上游应用版本及 `versionCode`。
- APK 文件名和最低 Android 版本。
- APK 文件的 SHA-256 摘要。
- 签名证书的 SHA-256 摘要。
- 该构建的验证范围和已知问题。

Windows PowerShell：

```powershell
Get-FileHash -Algorithm SHA256 .\downloaded.apk
```

Linux：

```bash
sha256sum ./downloaded.apk
```

macOS：

```bash
shasum -a 256 ./downloaded.apk
```

如已安装 Android SDK Build Tools，还可检查 APK 签名证书：

```bash
apksigner verify --print-certs ./downloaded.apk
```

请将本地输出与对应 Release 中公布的摘要逐项比对。摘要不一致时，不应继续安装。

## 版本迁移

每个官方版本都必须重新进行去广告和功能边界审查。历史记录用于定位思路和验证目标，不是可以直接套用的补丁。后续版本至少要重新完成：

1. 保存官方 APK 原件和 SHA-256，建立未修改对照目录。
2. 重新定位广告、学习/助手、账户、云同步、电脑端扫码、导入/导出分享入口、个人信息导出和 APK 更新调用链。
3. 只迁移经新版调用者、返回值和运行路径确认的修改。
4. 用 apktool 重建、zipalign、apksigner 和二次解包验证最终 APK。
5. 对比高校导入/解析目录，分别记录静态验收和真机回归状态，并保存独立回滚副本。

完整步骤见 [版本迁移与发布流程](./UPDATE_WORKFLOW.md)，具体版本映射见 [版本记录](./RELEASE_RECORDS.md)。

## 技术说明

项目通过解码 APK、调整 Android Manifest 与相关 Smali 入口、重新构建、对齐及签名生成发布包。处理范围集中在功能入口和组件声明，避免改动高校导入解析等核心课表逻辑。

维护资料：

- [版本迁移与发布流程](./UPDATE_WORKFLOW.md)
- [版本记录](./RELEASE_RECORDS.md)
- [Manifest 广告组件处理脚本](./scripts/disable_ad_components.ps1)

维护流程和脚本中的版本映射属于迁移参考资料，不代表对其他上游版本可直接复用。升级基线时，应重新核对类名、资源、组件和调用关系。

## 发布验收

每个发布版本至少应完成以下检查，并在 Release 中记录结果：

- APK 能够完成解码、重建和再次解析。
- APK 通过 `zipalign` 对齐检查。
- APK 签名及签名证书摘要符合预期。
- 已精简的页面、组件、权限和调用入口未重新出现。
- 普通更新提醒、强制更新分支、更新弹窗和手动版本检查未重新出现。
- 导入/导出分享口令、在线分享、导出菜单“分享 App”和个人信息导出入口未重新出现。
- 本地课表及高校导入相关代码路径保持完整。
- 未包含密钥、凭据、Cookie、个人教务数据或调试日志。

以上检查应分别标注静态分析、构建验证和真机回归结果；静态或构建通过不等同于覆盖所有设备和高校教务系统的完整运行测试。

## 隐私与网络

- 项目不新增账户、统计、广告或云同步数据上传逻辑。
- 高校课表导入仍需访问所选高校的教务系统。
- 教务账号、验证码和课表数据的处理仍取决于原应用导入实现及高校系统。
- 原 APK 中可能保留第三方库，禁用已知入口不代表完成形式化安全审计。
- 网络权限仍用于高校教务系统等必要网络流程；本项目不承诺原应用或第三方服务的服务器行为。
- 请仅使用来源和完整性均已确认的构建，并谨慎输入重要账号凭据。

## 已知限制

- 应用账户、会员、收藏和云端课表恢复不在支持范围内。
- 高校教务系统页面变化可能导致既有解析规则失效。
- 不同 Android 版本、系统定制和 WebView 版本可能存在兼容性差异。
- 项目签名与官方版本不同，不提供官方版本的无缝升级路径。
- 应用内更新功能是否可用取决于对应构建的精简范围；以可信 Release 的说明为准。
- 功能精简结果与上游版本相关，新版本需要重新分析和验证。
